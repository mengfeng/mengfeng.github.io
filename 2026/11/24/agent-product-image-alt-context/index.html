同一张马克杯照片，为什么要写三种 alt？

运营在商品编辑器里上传了一张钴蓝色马克杯照片。第一次把它放在商品详情里，照片能补充杯柄形状和内壁颜色。第二次用它装饰一段已经写清外观的文字，图片里的信息都在旁边。第三次把它作为进入「马克杯规格」的唯一链接内容，用户需要知道的是可以点它看规格。

如果系统在素材库只存一个 Agent 生成的 alt，每次插入都直接复制，第二个位置会让用户重复听到外观，第三个位置会让链接只读出杯子长什么样。示例让运营切换同一张照片的三种页面位置，在真正的 HTML 上下文中查看结果。商品照片为生成的演示素材，商品信息和模型候选都是固定样本。打开 Vue 交互示例 · 下载源码

图片在页面上的用途 示例结果 页面为什么这样做
详情图补充外观 钴蓝色马克杯，右侧有圆形杯柄，杯内为白色 用短句传达在这里有用的视觉信息
图片紧挨着等价的文字 alt="" 让辅助技术略过图片，保留旁边的描述
图片是链接的唯一内容 查看马克杯规格 让链接有能说明去向的可访问名称

依据 W3C WAI 的判断树，要先检查图片在当前页面中的作用。如果它是链接里唯一能说明用途的内容，就用替代文本描述去向或操作。如果链接里已经有等价的文字，旁边只是配图，空值可能更合适。真正遗漏 alt 时，部分屏幕阅读器可能朗读文件名。装饰分支应显式渲染空字符串，并保留页面上那段等价文字。W3C 图片替代文本判断树 · 装饰图片 · 功能图片

把页面用途和素材版本交给读取工具

示例假设编辑器有个只读工具 readImagePlacement(placementId)。它能读到当前位置的用途、图片版本和经内容编辑确认的可见细节。详情图快照登记了一张图的两个细节，分别用 handle 和 interior 标记。图片链接所做的动作来自页面配置，页面提前声明「查看马克杯规格」。装饰位置则在渲染过程中实际提供含等价信息的文字。

字段 由谁提供 用来检查什么
placement.id、imageRevision 编辑器及素材库 候选属于当前插槽和当前图片
role、actionLabel 页面配置 图片用途，以及图片链接的动作名称
subject、details 已确认的素材信息 允许组成替代文本的可见内容
placementId、imageRevision、role、detailIds Agent 候选 Agent 建议当前用途及要强调哪些细节

版本绑定要覆盖位置变化。运营可能保留一张图，只把详情图移进图片链接。图没有换，链接名称的要求却变了。示例校验位置、图片版本和用途。正式接入时还可以把相邻文案或链接目的的修改绑定到一次新的位置快照，避免员工改完按钮目标后，旧候选还能通过。若一种位置由模板固定，Agent 只需提出相关细节，页面可以直接提供该位置的用途。

让 Agent 选已确认的细节

候选从接口进入程序时按 unknown 接收。先核对结构、位置、版本和用途，之后再处理引用。详情图允许从当前快照选一到两条已登记的细节。程序检查每个 ID 都有效且只出现一次，最后按配置中的顺序拼接短句。模型如果引用了「可用洗碗机」这样的词，当前列表里找不到该 ID，页面就要求人工复核。安全的显示值都来自编辑器已确认的信息。

ts
const known = new Set(placement.details.map(detail => detail.id))
if (!ids.every(id => known.has(id)) || new Set(ids).size !== ids.length) {
  return { kind: 'review', reason: 'facts' }
}

const details = placement.details
  .filter(detail => ids.includes(detail.id))
  .map(detail => detail.phrase)

return { kind: 'ready', alt: placement.subject + '，' + details.join('，') }

这种拼接只适合本例的简单陈列照片。它依赖内容审核正确标注了当前素材、且登记细节能够独立连成一句话。如果照片是尺码表、带字活动海报或一张复杂图表，要先保留图中文字或完整说明。W3C 判断树也将复杂图与简单照片分开处理。示例的程序可以检查引用是否属于当前上下文，文字是否真正传达这张图的作用还需要人在页面中阅读。W3C 图片替代文本判断树

在 Vue 里预览真实标签，再让运营判断

程序返回 ready 时预览使用真实的 <img :alt="result.alt">。装饰图仍绑定一个空字符串，图片链接则在 <a> 里仅放一张图。链接导航到当前示例下方的规格区，因此读者能直接按 Tab 找到它，再用 Enter 验证目标。HTML 标准要求，在只有图片内容的链接或按钮中，图片的替代文本合起来要能说清链接或按钮的目的。Vue 绑定接收计算后的字符串，预览的结果区也同时显示属性值。HTML 标准的图片链接规则 · Vue 属性绑定

模型候选不适用于当前位置时，编辑器预览显示「需要人工复核」，并提示是旧图、位置不符或引用错误。它隐藏这次未通过的预览，不去修改对外页面。接到正式编辑器后，可以保留已经审核的旧稿，让运营定位图片并准备新草稿。最终保存时服务器应再次核对当前版本和操作权限。示例从头到尾只操作浏览器里的本地预览。

本地运行与验收

源码包含已打包的页面。解压后可以直接打开 index.html。如果要修改与重建，在解压目录执行以下命令，再打开 http://127.0.0.1:8077/。

sh
npm ci
npm run typecheck
npm test
npm run build
python3 -m http.server 8077
  1. 开始于「商品详情图」，核对照片、外观文字和 alt 显示。切到「图旁已完整描述」，页面仍能看到图片，但元素上应有显式的 alt=""。
  2. 选择「独立图片链接」，用键盘进入链接，再前往规格区。开发者工具的无障碍面板中应看到「查看马克杯规格」作为链接名称。
  3. 试一次误把链接当装饰，再分别切换到未经登记的卖点、过期图片和错误位置。四种候选均应进入复核，并且不会把旧场景里的可点击图片留在页面上。

离线测试覆盖用途中对空值的不同处理、重复细节和异常结构。浏览器检查可以验证真实标签、链接名称和键盘操作。正式发布前，还应在真实模板和目标辅助技术中检验文字是否准确、是否重复。这里未调用真实 Agent，也未评估模型识图或实际无障碍合规。
