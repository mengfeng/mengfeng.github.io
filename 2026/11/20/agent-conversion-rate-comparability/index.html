转化率降了，还是分母变了？让 Agent 先核对统计口径

2026-11-20
AI Agent

周报里的一个下降箭头

周一早上，运营在看板里问 Agent：“上周和本周的结账转化率差了多少？” 上周有 10,000 个进入结账的会话，其中 800 个完成付款。本周有 12,000 个进入结账的会话，其中 864 个完成付款。两期使用同一套定义，转化率分别是 8.00% 和 7.20%。付款会话数增加了，结账转化率下降了 0.80 个百分点，这两件事可以同时发生。

如果本周报表的 18,000 来自全部访问会话，拿它作分母会得到 4.80%。这个算式可以成立，但已经换了指标。把 4.80% 与上周的 8.00% 并排，再让 Agent 输出“结账转化率骤降”，会误导阅读周报的人。页面需要在展示结论前核对数字是怎么算出来的。

本例把这段流程拆成两次检查。看板先判断两份快照是否可比并复算差值，再审核 Agent 建议是否引用了这两份快照、给出的差值是否一致。读者可以切换八个场景，查看原始计数和每种结果。数据工具、模型候选和周报内容都使用虚构样本，代码运行在浏览器本地。打开交互示例 · 下载源码

先讲清楚一个会话被算了几次

示例的指标定义是“付款的结账会话数 ÷ 进入结账的会话数”。数据工具应按会话去重，分子从同一批结账会话中计算。一个会话里触发多次付款事件，在本例口径下仍然只计一个。这样分子才是分母的子集，分子大于分母时也就有明确的异常含义。这个约束只适用于本例的会话指标。真实系统即使叫“购买次数”，也可能按事件、订单或商品件数汇总，各有用途。Google 的电商指标文档举例说明了一次购买三件商品如何分别记为一次购买事件和三件商品。Google Analytics 电商指标文档

数据工具返回的每期快照除了计数，还有快照 ID、统计区间、口径和结算状态。版本用于追踪口径变更，分母单位、时区、渠道和覆盖天数让页面与排查者看得出具体有什么变化。下表中两周是演示工具预先选定的连续七天，边界由工具提供。只检查天数相同无法证明两个任意日期区间也适合做周环比。

字段 本例如何使用
id 绑定某周的计数快照，便于核对候选引用
definition 核对分母、版本、时区、渠道和覆盖天数
state 两期都已结算才生成差值
sessions 与 paidSessions 检查计数后复算变化

生产接口中，一个版本还应对应明确的归因规则。比如某会话周日晚上进入结账、周一才付款，到底计入哪一周，需要由数据方确定。若把订单时间按 UTC 聚合、会话时间按北京时间聚合，即使字段名一样，分子和分母也可能跨到不同日期。示例由固定工具提供每个时间窗口的聚合，重点是核对返回结果的定义和状态。实际分析平台的数据在处理期间可能变化，业务方可在工具契约里约定何时标记为已结算。Google Analytics 数据新鲜度文档

缺数据、零分母和零付款是三种情况

页面先看本周快照是否存在，然后检查计数是否为非负安全整数且分子不超过分母。接着核对是否结算、定义是否相同，最后检查分母是否为零。阻断时仍显示已返回的计数和快照状态，旁边给出重新查询、等待结算或按统一口径重算的提示。

  • 快照没返回时，页面显示“快照未返回”。这是工具查询状态，需要重新取数据。
  • 结账会话数和付款会话数都为零时，转化率未定义。界面不显示趋势数字。
  • 结账会话数大于零，付款会话数为零时，转化率为 0.00%。这是一条有效结果，可以参与比较。

用一个 value || 0 兜住所有空值会丢掉这些差异。周报看起来总能产出数字，排查时却不知道是工具没返回、渠道没有流量，还是确实没有付款。本例用 Comparison 的 kind 与 reason 表达比较状态，Vue 模板只在可比状态渲染百分比和差值。

百分点由页面复算，再检查候选

页面除法用未四舍五入的原始比率。将后一期比率减去前一期，再乘以 10,000 并四舍五入为整数基点。一个基点是 0.01 个百分点，所以 -80 对应 −0.80 个百分点。本例保留两位小数给周报阅读，计算链路不依赖展现在屏幕上的字符串。若业务选择报告相对变化，则公式还需要除以前期比率，分母为零时应另行处理。本例报告两期比率的直接差。

ts
const earlierRate = earlier.paidSessions / earlier.sessions
const laterRate = later.paidSessions / later.sessions
const difference = laterRate - earlierRate
const deltaBp = Math.round(Math.abs(difference) * 10_000) * Math.sign(difference) || 0

模拟 Agent 只返回一条结构化提议，带上两个快照 ID 和整数基点差值。收到提议时，代码从 unknown 开始检查，确认当前可以比较，核对快照 ID，再对整数差值做严格比较。代入过时的快照 ID，即使差值相同也不会通过。若候选报的是 −800 基点，页面仍可展示独立复算的 −80 基点，同时阻断该候选进入周报草稿。通过检查只代表“引用和数值一致”。描述下降的原因仍需额外证据，整体比例下降本身无法诊断支付故障或某个渠道质量变化。

显示绝对比率时，Intl.NumberFormat 的百分比格式接受小数比率，输入 0.072 得到 7.20%。显示差值时，将基点除以 100，再添加“个百分点”标签。Vue 的 computed() 把当前场景的快照、比较结果和候选审核状态串起来，切换场景后模板使用同一份派生结果。实际请求数据或调用模型应由独立动作触发，计算属性只处理已有数据。MDN 百分比格式 · Vue 计算属性

运行与验证

解压源码包后，可以直接在浏览器打开 index.html。要核对源码或改动后重建，在解压目录运行下面的命令，然后访问 http://127.0.0.1:8765/。

sh
npm ci
npm run typecheck
npm test
npm run build
python3 -m http.server 8765

先选“两周口径一致”，核对 800 ÷ 10,000 和 864 ÷ 12,000。切到“本周改用全站会话作分母”，检查页面停止展示变化。依次尝试“本周无结账会话”和“有结账会话，付款数为零”，确认两个零值的处理不同。最后模拟错差值或旧快照，观察独立复算结果仍在，模拟候选无法通过。

离线测试覆盖这些分支、异常计数、时区不一致和字段类型错误。接到真实数据服务后，还要校验外部响应字段、账户和渠道权限，以及服务端选取的时间窗口。真实周报可以保留快照 ID 供复查，并在用户审阅后再执行发布动作。
