# Agent 解决不了，带着上下文转交

Vue 3 + TypeScript 的纯浏览器离线会话摘要与人工转接入口演示。会话、物流、模型与队列均为教学模拟。没有真实模型 API、CRM、客服通知、业务工单、外部消息或真人接入。保存只写入当前浏览器页面的内存 Map，刷新会清除。

## 直接运行

解压完整 `source.zip` 后，双击 `index.html` 打开已构建页面。页面和 Vue bundle 不依赖外部 CDN。也可在解压目录执行：

```sh
python3 -m http.server 8094 --bind 127.0.0.1
```

访问 `http://127.0.0.1:8094/`。这是静态文件服务，不是模型或业务 API。

## 从 TypeScript 构建

需要 Node.js 20+（本例以 Node.js 24.22.1 验证）和 npm。首次安装需要从 npm 下载锁定的 Vue 3.5.43、TypeScript 5.7.2、esbuild 0.28.2。安装后，类型检查、测试和构建不调用模型或外部业务接口。

```sh
npm ci
npm run typecheck
npm test
npm run build
```

`app.js` 已由 `src/app.ts` 构建。`npm test` 临时构建并运行 `.test.mjs`，完成后删除。本例包含 32 个核心离线用例；浏览器与文章预览验收由主发布流程另行记录。

## 演示步骤

1. 初始会话为：“我想查询演示订单 DEMO-1001 的物流进度。”点击一次“模拟查询失败”，连续失败为 1，不能自动准备摘要；第二次为 2，提示建议转人工，但不会生成、保存或发送工单。
2. “模拟查询成功”将连续失败归零。此处只追加固定模拟工具消息，没有真正查询物流接口。
3. 不必先失败两次，用户可随时点击“我希望转人工”，再生成摘要。
4. 摘要的问题字段取首条用户原文，期望字段为固定的待人工核对说明。完整会话与所有工具尝试原文通过来源展开，不做自由生成的压缩事实、推断或承诺。
5. 模拟模型仅返回当前会话版本和原消息 ID/原文引用集合；执行层校验全部来源，然后构造两个可编辑字段。使用故障选项“引用不存在的消息”时拒绝摘要。
6. 编辑“问题摘要”和“希望如何处理”，点击明确确认后，才把这份编辑稿的不可变快照送进内存队列。保存期间锁定会话、编辑和重复确认，防止悄悄保存后改内容。
7. 选择“明确写入前失败”：没有队列写入，页面保留编辑稿；可改为正常保存重试，也可复制。复制不可用或被拒绝时，显示可选中文本，不显示“已复制”。
8. 正常保存后显示“已进入本页演示队列 · 未接通真人”和 `DEMO-1` 回执。这只代表已核对模拟回执，不代表人工客服已收到或已接手。
9. 选择“已写入但回执版本错误”：队列 Map 实际有记录，页面却不能核对其回执，因此进入“入队结果待核对”。保留原操作编号与摘要，锁定编辑；同编号重试返回既有回执，不重复创建。未知结果不能被后续失败错误地降级成“尚未保存”。
10. 保存前补充会话、查询或重置会立即清空旧摘要；迟到摘要不会覆盖新会话。重置保留本页已核对的队列记录；刷新页面才清除全部数据。

## 数据、来源与确认边界

会话为 `{version, messages, failures, manual}`，每条消息只有受控 `id`、`role`、`text`。会话最多 30 条消息，补充消息与两个编辑字段均为 1–300 个 JavaScript 字符串长度单位，不能全为空白。来源与编辑字段按 Vue 文本节点显示，没有 HTML 渲染或由材料提供的外部链接。

模拟摘要输出只有：

```json
{"sourceVersion":2,"sources":[{"id":"v1-m1","quote":"我想查询演示订单 DEMO-1001 的物流进度。"},{"id":"v2-manual","quote":"我希望转人工处理。"}]}
```

执行层要求来源数量、顺序、ID 和全文与当前会话快照一致，拒绝多余审批字段、伪造版本、遗漏或篡改的原文。模型不提供可自由追加的摘要事实；默认问题来自首条原始用户消息，期望处理为固定模板。用户随后编辑的文字明确属于用户确认内容，不冒充原始会话或已核实业务事实。订单和物流文字都是虚构数据；引用存在也不能证明真实业务已发生。

确认快照为：

```ts
{ operationId, sourceVersion, revision, issue, expected, sources }
```

提交保留用户可见编辑字符串，包括首尾空格；输入校验只判断非空、长度等约束，不把保存内容悄悄改成另一份文案。失败重试沿用同一编号和内容。明确写入前失败后，用户重新编辑会产生新操作；结果未知时不允许编辑，须先核对原操作。队列先查已有编号，再注入新写入前失败，避免对已存在记录谎报未保存。

回执必须严格包含 `ticketId`、同一确认快照全部字段和 `status: 'queued-demo'`。只有字段与原文完整匹配的回执才可显示已核对队列项。客户端代码和 Map 用于教学，不是服务端鉴权、持久幂等或真实工单可靠性保证。

## 异步与失败范围

摘要任务按会话版本与任务代际隔离。保存期间锁定本地编辑，页面卸载后旧回调不再更新 UI；这不表示撤销已经执行的保存。剪贴板异步结果也按任务代际隔离，不让旧复制成功覆盖新稿的失败提示。已经交给系统的剪贴板动作无法可靠撤销，因此状态保护不承诺能回滚系统剪贴板。

明确的失败模式发生在保存之前，便于可重复验证草稿保留。错误回执模式刻意模拟“实际已入队但客户端无法确认”，用同一操作编号恢复。队列和操作编号只在当前页面生命周期有效，不能用来声称跨刷新、跨标签页、跨设备或生产环境幂等。

真实接入时，须由服务端执行身份、权限、会话归属、确认快照、幂等和持久化检查；客服系统的排队、人工接受、拒绝、断开还需要单独事件和状态。当前演示没有那些真实接口，也没有评估真实模型摘要质量、客服接通率或业务收益。

## 文件

- `src/core.ts`：固定会话、失败阈值、原文校验、可编辑稿、确认快照、演示队列与恢复状态。
- `src/app.ts`：Vue 会话、编辑、确认、复制降级和已核对队列界面。
- `test.ts`：32 个核心离线测试。
- `验证结果.json`：类型检查、测试与构建记录。
- `VUE-LICENSE.txt`：打包 Vue 的 MIT 许可。
