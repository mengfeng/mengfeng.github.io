# 建议属于哪个购物车版本？

Vue 3 + TypeScript 的购物车凑单建议与过期结果演示。商品、价格、库存、门槛及模型计划全为教学模拟数据。没有真实模型 API、订单、付款、优惠结算或自动加购。界面加减按钮只改变当前浏览器内存中的演示购物车。

## 直接运行

解压 `source.zip`，双击 `index.html` 即可运行构建好的离线页面；页面和 Vue bundle 不依赖外部 CDN。也可在解压目录执行：

```sh
python3 -m http.server 8093 --bind 127.0.0.1
```

访问 `http://127.0.0.1:8093/`。静态 HTTP 只提供页面文件，不是模型或业务 API。

## 从源码构建

需要 Node.js 20+（本例实际使用 24.22.1）与 npm。首次安装从 npm 下载锁定的 Vue 3.5.43、TypeScript 5.7.2 与 esbuild 0.28.2；安装后的类型检查、测试、构建不调用模型或外部业务服务。

```sh
npm ci
npm run typecheck
npm test
npm run build
```

`app.js` 已由 `src/app.ts` 构建。`npm test` 构建临时 `.test.mjs`，运行后删除。`test.ts` 包含 25 个离线用例。

## 观察当前、过期与重新查询

1. 初始购物车 v1：演示笔记本 ¥32 × 2，加演示签字笔 ¥12 × 1，合计 ¥76。固定演示门槛 ¥100。
2. 点击查询：固定模拟模型提出一次 `findTopup` 调用，工具对快照计算，显示短线 ¥24 × 1，模拟商品总计 ¥100。没有实际加购。
3. 签字笔加 1：当前购物车变成 v2、合计 ¥88，旧建议立即隐藏并标为过期。重新查询会得到夹子 ¥6 × 2，新建议来源 v2。
4. 将延迟切到 2500 毫秒，发起查询后修改数量：旧响应不能覆盖过期提示。
5. 同一查询期间把签字笔数量从 1 改为 2，再改为 1：合计仍是 ¥76，但购物车已是新版本。旧请求不能因金额相同而恢复有效，这是 ABA 场景。
6. 同一版本连续查询，只接受最新请求；旧成功或旧错误都不能覆盖新任务。
7. 在故障选项中选择未知商品、错误金额、伪造版本或多次调用，再查询：拒绝本轮全部结论，旧建议不保留。
8. 笔记本加到 3 本可达到门槛，不建议额外购买。删除所有笔记本，只留下 1 支签字笔时，无库存足够的单 SKU 达标方案。清空后显示空车，不诱导凑单。

## 版本与任务的两道检查

`changeQuantity` 是统一的有效数量变化入口，同步产生新快照并把版本加 1。加减、删除、重新加入都经过它；恢复初始车和清空也产生新版本。设置为当前相同数量是 no-op，不算业务变化。即使恢复出的商品内容与初始相同，也不会复用旧版本号。

控制器每次查询还产生独立递增请求序号。接收异步结果之前检查：

```ts
if (request !== generation || source.version !== cart.version) {
  return;
}
```

购物车变化时立即清空旧建议并标记 stale，不等旧请求返回才处理。查询使用运行时冻结的独立快照；模拟模型无法改写它。旧错误同样经过序号与版本检查。取消/失效仅限制本页接收结果，不表示撤销远端操作；本例没有远端操作。

## 工具与输出结构

固定模拟模型只生成计划，不生成自然语言结论：

```json
{"calls":[{"name":"findTopup","arguments":{"cartVersion":1}}]}
```

执行层只放行一次 `findTopup`，参数只能包含本轮快照版本，不接受模型提供的 SKU、价格、任意购物车内容或第二个工具。工具用受控目录与该快照计算候选。所有金额以整数分计算。

工具结果如下：

```json
{"sourceVersion":1,"subtotalCents":7600,"gapCents":2400,"kind":"topup","sku":"cable","quantity":1,"addedCents":2400,"finalCents":10000}
```

`validateSuggestion` 从可信目录和当前快照重算完整结果，严格检查字段集合及所有值，不直接渲染未经检查的工具对象。种类可以是 `topup`、`covered`、`empty` 或 `unavailable`；无加购方案时 SKU 为空串，数量与新增金额为 0。

候选固定为短线 ¥24（库存 3）、便签 ¥9（库存 5）、夹子 ¥6（库存 5）和收纳袋 ¥20（库存 0）。每个候选 SKU 计算达到门槛所需的最少整数件数，并扣除车内该 SKU 已有数量后的可用库存。仅比较“一个候选 SKU 的若干件”方案：先最少新增金额，再最少件数，再 SKU 名排序。它不是跨 SKU 组合的全局最优，也不是经济购买建议。凑够门槛可能意味着多花钱，本例未模拟实际运费，因此不声称能省钱。

## 验证范围

已运行类型检查、25 个离线测试及构建；浏览器与公网验收由发布流程单独记录。测试覆盖正常金额、缺货、空车、达标、非法参数、伪造输出、请求中修改、ABA、最新请求、旧错误、清空和重置、快照不可变以及无自动加购。

这是确定性工具加固定模拟模型计划，没有真实模型推理、后端、多标签页或多账号同步。版本号只在当前页面生效，刷新恢复初始购物车。不能把本地单调版本当作跨设备一致性机制。

真实系统应把购物车、商品价格、库存、优惠等会影响结论的版本纳入快照，服务端重新校验授权和状态，并在后续真正写入之前执行条件检查。前端过期提示不能代替服务端条件写入；本例没有实现该写入路径。

- `test.ts`：25 个离线核心用例。
- `验证结果.json`：实际类型检查、测试及构建记录。
