# Agent 地址修改草稿与版本确认演示

Vue 3 + TypeScript。固定模拟模型只识别输入中的“前台 / 驿站”，生成演示地址草稿，不做真实自然语言理解。姓名、联系方式与地址均为占位；不调用真实模型、订单、地址服务或对外消息。

## 两种运行方式

解压直接打开 `index.html`，或通过普通静态预览服务打开：使用浏览器内的离线模拟服务，所有状态只保存在该页面内存。公开 GitHub Pages 演示也使用这条路径，没有查询网络请求，不运行 Node。

源码包提供真实本地 HTTP 路径，使用 Node.js（本次 Node 24.22.1 验证）运行：

```sh
npm run serve
```

浏览器访问 <http://127.0.0.1:8089/>。本例固定端口 8089；只有这个 loopback HTTP 页面自动使用同源 API，其余页面均为离线模式。不要用普通静态服务占用 8089，否则页面会请求不存在的 API。服务只监听 127.0.0.1，不支持部署到公网。

HTTP 服务仅使用进程内存，重启全部清空；离线页面刷新同样清空。两种模式复用 `src/service.ts` 的草稿/预览/确认规则，但传输路径不同。已构建 `app.js` 和 `service.mjs` 随包提供，直接运行无需安装依赖或模型 Key。

## 重建与测试

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run test:http
```

重建时需要 npm 网络下载依赖：Vue 3.5.43、TypeScript 5.7.2、esbuild 0.28.2。执行 HTTP 集成测试前，先关闭同端口演示服务；测试自行启动并关闭本地服务。

## 操作顺序

1. 点击“生成模拟草稿”：把演示地址填到驿站，尚未保存。
2. 手工修改字段（必须使用演示占位），点击“预览变更”。先将字段同步为服务端草稿新版本，再签发一次确认令牌，展示旧地址 → 新地址；保存次数仍为 0。
3. 预览后字段锁定。点击“修改此草稿（撤销确认）”：先请求服务端废弃确认令牌，成功才解锁字段；重新生成也先撤销。撤销失败时保留锁定与旧预览，不能假装已进入编辑。
4. 重新预览会同步新版本；旧版本、旧令牌无法确认。点击“确认保存此版本”才保存服务端持有的预览快照。
5. 成功令牌只能使用一次，连续提交不能增加第二次保存。
6. 勾选“模拟保存失败”再确认：令牌消费但地址不写入、保存次数不增加，UI 显示失败；必须重新预览后再尝试。

表单校验：收件人须以“演示”开头、联系方式只能是 `DEMO-` 加四位数字、地址须以“演示”开头，字段有长度上限。这里只验证演示字段格式，不提供真实电话或地址校验。

## 共享规则与接口

- `GET /api/state`：读取演示草稿、已保存地址和保存次数。
- `PUT /api/draft`：`{baseVersion, fields}`；乐观版本检查后增加版本并废弃旧预览。
- `POST /api/preview`：`{version}`；返回 `{version, token, before, after}` 快照；同版本再次预览会替换旧令牌。
- `POST /api/invalidate`：`{version}`；明确废弃确认资格，随后才能开放修改。
- `POST /api/confirm`：`{version, token, failSave?}`；地址从服务端预览快照取得，不从确认请求中取得。校验版本/令牌、消费令牌、内存保存之间无 await，避免并发重复保存。

`createWorkflow(api, publish)` 提供 init、edit、prepare、beginEdit、confirm、dispose；异步响应按操作序号核对，不能晚到后恢复旧预览或覆盖新状态。Vue busy 时锁定修改、生成与确认入口；组件卸载后不再发布状态。

## HTTP 边界与限制

静态资源严格白名单：根页、index.html、app.js、style.css。写接口要求 application/json，按字节限制请求体最多 2048；超限拒绝，不写状态。Host 仅接受 127.0.0.1:8089 / localhost:8089；若携带 Origin，仅接受对应 loopback 同源；不提供 CORS。

这些是本地演示的边界，不是生产鉴权。无 Origin 的本机客户端仍可以调用；全服务只有一个演示草稿，不隔离多账号。确认令牌没有用户绑定、有效期或持久化；真实地址服务必须加入会话授权、账号归属、过期时间、数据库并发控制与审计。进程崩溃、网络响应丢失后的写结果不确定性不在本例范围，不能将 UI 报错等同于真实服务未写入。

## 已执行验证

16 组核心测试：草稿不写、明确确认、重复消费、版本变化、主动撤销、重做预览、保存失败、快照不可被返回对象修改、UI 撤销与撤销失败、迟到响应与卸载等。

12 个真实 loopback HTTP 断言：状态/草稿/预览/撤销/保存失败/并发重复确认/旧版本/跨 Origin/错误 Host/静态白名单/内容类型/请求体上限。这里的 HTTP 真实指浏览器或测试客户端到本地 Node 的传输，模型与业务仍全部模拟。

`验证结果.json` 记录本候选的命令与 app.js 哈希；浏览器交互验收由博客发布流程另存，不将离线测试写成真实模型验证。
