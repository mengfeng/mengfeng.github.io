## 燕麦色有货，S 码也有货，为什么燕麦色 S 码买不到？

顾客在导购窗口里说「我想买燕麦色，S 码」。工具返回的清单里，燕麦色 M 码有货，炭灰色 S 码也有货，但燕麦色 S 码已经售罄。如果 Agent 分别读「有货颜色」和「有货尺码」两个列表，就可能把来自不同 SKU 的条件拼到一起，告诉顾客所选组合有货。

页面应当先把颜色和尺码当成一个组合，查出对应 SKU 的状态。若原组合确实售罄、顾客允许换颜色，再找同尺码的备选。即便备选有货，也先让顾客看见具体变化，点击后才改变选择。演示只使用虚构衬衫、固定库存和模拟 Agent 响应。采用备选只更新本地页面，不产生订单或库存写入。[打开 Vue 交互示例](/examples/agent-variant-stock-alternative/) · [下载源码](/examples/agent-variant-stock-alternative/source.zip)

## 把父商品和当前组合分开读取

假设只读工具是 `readVariantSnapshot(groupId, stockScope)`。每条记录关联一个颜色、一个尺码和一个 SKU，工具同时提供清单是否完整与当前快照 ID。Google Search Central 的商品结构化数据文档也用 `ProductGroup` 表示商品组，用 `variesBy` 声明颜色、尺码等区分维度，用 `hasVariant` 连接实际变体。这里借用的是同样的父子商品建模方式，库存判断由业务数据完成。[Google 商品变体文档](https://developers.google.com/search/docs/appearance/structured-data/product-variants) · [Schema.org ProductGroup](https://schema.org/ProductGroup)

| 字段 | 由谁提供 | 前端用在哪里 |
| --- | --- | --- |
| `groupId`、`snapshot.id` | 只读工具 | 限定当前商品和具体库存快照 |
| `complete` | 规格读取工具 | 区分未配置的组合和尚未拿到的记录 |
| `variantId`、颜色、尺码、库存状态 | 规格与库存工具 | 渲染该组合的当前状态 |
| 选中的颜色、尺码、是否允许换色 | 用户交互 | 限定建议范围，保留尺码要求 |
| 商品组、快照 ID、原选择、备选 SKU ID | 模拟 Agent 候选 | 定位建议，供程序查找和复核 |

正式接口中，快照还需绑定库存范围，例如渠道、发货地或提货门店。调换门店可能让同一个 SKU 得到不同答案。快照 ID 应唯一指向本次数据及其生效条件，切换范围后按新快照重查。当前示例把这些条件固定在单个演示范围里，没有引入跨仓判断。

## 清单里找不到一行，先看清单是否完整

前端按两项选中值匹配。恰好一行时读该行库存；多行时标记数据冲突；缺行时检查完整性。完整清单缺了燕麦色 S 码，说明该组合未配置。清单还在分页、部分请求失败或尚未返回完整时，缺行只表示此刻无法判断。另有一种情况是规格存在而库存读取失败，工具会返回 `unknown`，页面仍提示重新查询。

```ts
const matches = snapshot.variants.filter(row =>
  row.color === selected.color && row.size === selected.size
)
if (matches.length > 1) return { kind: 'conflict' }
if (matches.length === 1) return { kind: matches[0].stock }
return { kind: snapshot.complete ? 'not-offered' : 'unknown' }
```

不同状态对应不同的下一步。售罄是已查到当前记录但没货，可以在顾客允许时给同尺码备选。未配置时，可以从已经查到且有货的组合里提出备选。未知和冲突需要先刷新数据或核对目录，以免因为一次查询不全就让顾客改掉原本买得到的颜色。演示让所有颜色和尺码选项保持可切换，并在旁边展示交叉库存表，方便顾客比较自己尝试过的组合。

## Agent 提出备选 SKU，程序核对三个条件

候选只给结构化字段，库存和颜色名由应用读取。第一步检查用户是否勾选允许换色，以及原组合是否确定不可用。第二步核对候选绑定的商品组、快照、原颜色和原尺码。顾客改选或库存更新时，旧候选需要重新核对。第三步查找候选 ID，确保它唯一存在、颜色确实发生了变化、尺码沿用原值，且新组合在当前快照有货。两个 SKU ID 都指向同一组颜色与尺码时，也会触发冲突判断。

例如 Agent 给出炭灰色 M 码，库存确实有货，但顾客只授权换颜色。页面会保留燕麦色 S 码，并提示当前备选未通过核对。若 Agent 声称来自最新快照，但候选 ID 实际已经找不到，同样处理。示例把这些问题合成一条给顾客的提示，开发侧可按数据失配、库存变化和约束不符分别记录原因，以便排查工具质量。

## 让用户看到变化，再决定采用

Vue 用 `v-model` 绑定颜色、尺码与换色选项。当前库存与备选建议由 `computed()` 随快照和条件重新计算。切换演示场景会清空之前的换色授权，手动改选后旧候选也不再跟随。顾客点击「切换到 炭灰色 / S」时，事件处理器才更新选择。按钮随即消失，焦点移到新状态上，让键盘用户能够继续核对结果。[Vue 表单绑定](https://vuejs.org/guide/essentials/forms.html#select) · [Vue 计算属性](https://vuejs.org/guide/essentials/computed.html#best-practices)

库存展示的是某个快照的结论。有货不代表已锁定，也不保证下一次提交还会有货。接入真实购物车后，服务端仍需核对最新 SKU 状态、价格、限购和权限。若商品在确认前失效，应保留最新选择，清除过期库存结果，并提示重新查看。本文的交互示例停在选择环节。

## 本地运行和验收

源码包附带打包后的页面，解压后打开 `index.html` 即可离线体验。若需修改和重新构建，在包内运行以下命令，再访问 `http://127.0.0.1:8077/`。

```sh
npm ci
npm run typecheck
npm test
npm run build
python3 -m http.server 8077
```

1. 默认燕麦色 S 码显示售罄，但同色 M 码和炭灰色 S 码均有货。先勾选允许换色，再核对候选与初始选择，点击后才切换到炭灰色 S 码。
2. 对照两种缺行场景。完整清单缺行显示「未配置这个组合」，部分清单缺行显示「库存待确认」。库存读失败也要显示待确认。
3. 分别切换尺码不符、旧快照和备选售罄三类情况。重新勾选换色后，页面保留原选择，并说明备选未通过核对。
4. 改选已有货的燕麦色 M 码，即使开着换色选项，旧的 S 码候选也不会再显示。

离线测试加上浏览器检查，验证的是固定输入与页面状态能否对应。正式接入模型时，还需要验证它能否识别顾客给出的硬性条件、找到合适的现货 SKU，以及是否能在没有符合条件的备选时答得准确。
