运营改到一半，Agent 的文案建议回来了，怎么合并？

2026-11-27
AI Agent

Agent 回来的时候，运营已经手动改过了

商品编辑器打开的是「午后马克杯」。运营让 Agent 润色卖点说明，继续把标题改成「海盐蓝马克杯」。几秒后，Agent 返回「握柄宽大，适合日常热饮」。这句建议可以合入说明，运营刚改的标题应该留在草稿里。

如果 Agent 也给了新标题「海边午后马克杯」，标题就出现了两种修改。这时用整份结果覆盖会丢掉人工选择，直接放弃建议也会失去可以合入的说明。编辑器可以逐字段比较三份内容，在同一行展示原版、当前草稿和 Agent 建议，再让运营决定冲突字段保留哪一版。打开 Vue 交互示例 · 下载源码

演示商品和候选都使用固定样本。点击应用只更新当前页面内存中的草稿，不会写入商品后台。

生成建议时记下它是基于哪一版

接入时，可以让只读工具 readProductCopy(productId) 返回当前三项可编辑字段和版本号。发起改写时冻结这份 base，之后的人工编辑写入 local。Agent 响应里带回商品 ID、原始版本和它建议更新的 patch。本例只有标题、卖点说明、角标三个字段，前端先检查候选的实际形状，只接受这些已开放字段。

数据 由谁提供 为什么保留
base 发起生成时的快照 知道双方是在什么基础上改的
local 编辑器当前输入 保留生成期间的人工修改
patch Agent 候选 只表达模型主动提出的字段修改
字段取舍 用户 决定有冲突时采用哪个值

合并前先对照候选的商品和基础版本。只要候选属于旧版本或另一个商品，页面就不展示合入入口。这里用 unknown 接收响应，确认对象及各字段类型之后才进入计算。比如带回普通文案之外的价格字段，整份候选会进入异常提示。TypeScript 类型收窄

三方比较要知道谁修改了字段

可以把这个问题理解成字段级的三方合并。Git 的 merge-file 会拿当前文件、共同基础版本和另一份改动做比较，双方改到同一段时需要处理冲突。这里借用共同基础版本的思路。示例把整个字段作为比较单位，标题里的两个词即便分别被改过，也会把整条标题交给运营检查。Git 三方合并说明

当前值与建议相对原版的变化 页面结果
双方都没改 保留当前值
只有运营改了 保留人工修改
只有 Agent 改了 放入合并预览
双方写成了同一个值 现有草稿已经包含结果
双方改了，而且值不同 展示冲突并要求选择

还要区分「字段没出现」与「明确清空」。候选没有提到角标时，建议值回落到原版，运营手动改过的角标会继续保留。候选给出 badge: '' 时，空字符串就是建议删除角标。解析阶段允许角标为空，同时检查候选标题和说明包含内容。

ts
const original = base.copy[field]
const current = local[field]
const suggested = patch.get(field) ?? original

if (suggested === original) return keep(current)
if (current === suggested) return keep(current)
if (current === original) return use(suggested)
return requireDecision(field, current, suggested)

这段代码用简化的函数名说明分支。源码还会记录每个字段的状态、选择与最终值，并在存在待处理的冲突时暂不返回可应用的草稿。新文本按原字符串比较。接入富文本时，编辑器需要先约定哪些格式差异属于真实修改，以及要以字段、段落还是结构节点为单位合并。

选过一边后，继续编辑要让旧决定失效

选择「采用 Agent 建议」是针对当时屏幕上那组标题做的决定。如果运营随后又重写人工标题，原来的决定不再充分，页面需要让这个冲突重新确认。示例在字段输入时清除该字段的选择，并在计算时再次核对选择对应的人工值。若线上有新一批候选替换旧候选，取舍还应绑定候选 ID 或建议值。

Vue 的 computed() 只根据当前草稿与候选生成预览。文本框编辑、冲突单选和应用动作通过组件事件修改数据。只有不存在待选冲突且确有修改时，才显示「应用到本地草稿」。应用后消化这次候选并把焦点移到确认信息，表单仍可继续编辑。Vue 表单输入绑定 · Vue 计算属性

这个示例集中处理同一编辑器里出现的改动。若还有其他同事在后台更新同一个商品，真正提交时应由服务端再核对商品及版本。版本变了就取新快照、重做比较并请运营确认。把确认后的草稿和原版一并留作记录，也便于日后说明是哪一处人工选择影响了结果。这里没有商家接口，也没有执行任何对外写操作。

本地运行和验收

源码包带有已打包页面，解压后打开 index.html 便可使用。若要改源码并重新构建，在包内运行下列命令，再访问 http://127.0.0.1:8077/。

sh
npm ci
npm run typecheck
npm test
npm run build
python3 -m http.server 8077
  1. 预览双方修改不同字段。确认人工标题保留，应用后只有卖点说明发生变化。
  2. 切到标题冲突场景。确认未选择时不能应用，选择后继续编辑标题，观察原取舍失效。重新选择一边，再应用到草稿。
  3. 查看双方写成同样标题和建议清空角标，检查前者无需重复合入，后者可以明确把角标改成空值。
  4. 切到版本过期或未开放字段，确认原文保留，页面提示重新生成或处理异常结果。

离线测试覆盖字段级决策和候选验证。它验证的是固定场景下的合并行为。接入真实模型后，还需要单独测试生成内容是否符合品牌语气和页面要求。
